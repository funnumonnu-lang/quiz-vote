# 投票クイズ — GitHub Pages + GAS/スプレッドシート版

出題者が **1問ずつ**「投票を開ける → 締め切る → 結果を発表」を進める方式です。
参加者はスマホで回答し、締め切るまで結果は誰にも見えません。

```
index.html（GitHub Pages）  ──fetch──▶  Apps Script /exec  ──▶  スプレッドシート
                                                                 rooms / votes
```

---

## 1. スプレッドシートとApps Scriptを用意する

1. Googleドライブで新しいスプレッドシートを作成（名前は任意、例：投票クイズDB）
2. メニューの **拡張機能 › Apps Script** を開く
3. `コード.gs` の中身をすべて消し、`gas-code.gs` の内容を貼り付ける
4. **フロッピーディスクのアイコン（Ctrl+S / ⌘+S）で保存** ← 保存しないと次の手順で関数が選べません
5. 上部の「▷ 実行」「🐞 デバッグ」の右にあるプルダウンで、**`doGet` から `setup` に切り替える**

   > ここが最大のつまずきどころです。`doGet` のまま実行しても「実行完了」と出ますが、
   > シートは作られません。**必ず `setup` に切り替えてから**実行してください。

6. 「▷ 実行」を押す → 初回は承認画面が出ます
   - 「権限を確認」→ 自分のアカウントを選択
   - 「このアプリはGoogleで確認されていません」→ 左下の **詳細** → **（プロジェクト名）に移動（安全ではないページ）** → **許可**
   - 自分で書いたスクリプトなら必ず出る警告です
7. 実行ログに `シートを準備しました: https://...` と出れば成功
8. スプレッドシートのタブを再読み込みし、**rooms** と **votes** の2タブができていることを確認

## 2. ウェブアプリとしてデプロイする

1. 右上の **デプロイ › 新しいデプロイ**
2. 種類の選択（歯車）で **ウェブアプリ**
3. 設定
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. デプロイ → 表示された **ウェブアプリURL（末尾が `/exec`）をコピー**

動作確認は、コピーしたURLの末尾に `?action=ping` を付けてブラウザで開きます。
`{"ok":true,"ver":2}` と表示されれば成功です。**シークレットウィンドウでも**同じ表示になるか確認してください。

> コードを直したら、そのつど **デプロイ › デプロイを管理 › 編集（鉛筆）› バージョン＝新バージョン › デプロイ** で反映します。
> 「新しいデプロイ」を繰り返すとURLが変わってしまうので注意してください。

## 3. index.html に接続先を書く

`index.html` の上のほうにある1行に、コピーしたURLを貼ります。

```js
const API_URL = 'https://script.google.com/macros/s/……/exec';
```

空のままでも動きますが（初回に設定画面が出て、参加リンクにも接続先が載ります）、
**書いておくほうが参加リンクが短く、確実です。**

## 4. GitHub Pages に置く

1. リポジトリに `index.html` を置く
2. Settings › Pages › Source を `main` ブランチのルートに設定
3. 公開されたURLを開いて動作確認

`file:///C:/...` のようにローカルのHTMLを直接開くと通信が遮断されることがあります。
テストは必ず `https://` のURLで行ってください。

## 進行のしかた

| 場面 | 出題者の操作 | 参加者の画面 |
|---|---|---|
| 準備 | 設問と正解を編集 →「クイズを始める」 | 「まもなく始まります」 |
| 出題 | 「この設問の投票を開ける」 | 設問と選択肢が出る（押すと即送信） |
| 集計中 | 回答人数がリアルタイムに増える | 選んだ記号が下部に表示 |
| 締切 | 「投票を締め切る」 | 「締め切りました」＋自分の回答 |
| 発表 | 「結果を発表する」 | 集計・正解・自分の○× |
| 次へ | 「次の設問へ」 | 待機画面に戻る |
| 終了 | 最終問で「全体成績を発表する」 | 自分の正解数と順位 |

- 番号のチップを押すと任意の設問へ移動できます（緑＝発表済み）
- 「投票を再開する」「もう一度投票する」で同じ設問をやり直せます
- 出題者の画面は発表時にそのまま集計が出るので、スクリーンに映して使えます

## 結果を伏せるしくみ

- 参加者に送るデータは、**到達済みの設問だけ**です。先の設問文や選択肢は届きません
- 正解は**発表済みの設問だけ**返します
- 集計（`results`）は、参加者には発表済みの設問ぶんしか返しません
- 出題者も投票中は人数しか取得しません

## データの場所

`votes` シートに 1人1行。列は `room / pid / name / answers / answered / updatedAt` で、
`answers` は `{"0":[1],"1":[1,2]}` のような設問番号→選択肢番号の対応です。
整形済みの表が必要なら、アプリの **CSVで保存** が早いです。

## 規模の目安

- 参加者の画面は3秒ごとに問い合わせます（1問ずつ進めるためテンポ優先）
- 40〜50人程度までは余裕があります。それ以上なら `index.html` の `POLL` を 5000 に上げてください
- サーバー側は3秒間キャッシュするので、人数が増えてもスプレッドシートの読み込み回数は増えません

## うまく動かないとき

| 症状 | 確認すること |
|---|---|
| setup を実行してもタブが増えない | プルダウンが `doGet` のままになっていないか |
| 「つながりません」 | URLが `/exec` で終わっているか。アクセスできるユーザーが**全員**か |
| 直したのに反映されない | デプロイの**バージョンを新しく**して再デプロイしたか |
| 参加者だけ入れない | 参加リンクに `api=` が付いているか。または `API_URL` を書いて再アップロードしたか |
| 「出題者の権限がありません」 | ブラウザの保存データを消していないか。別端末では進行できません |

## バージョンを入れ替えたとき

`rooms` シートに `cur / qphase / revealed` の3列が自動で追加されます。
以前の版で作った部屋は進行状態を持たないので、**作り直してください**（新しく部屋をつくるだけです）。
`rooms` シートの古い行を手で削除しても構いません。

## 社内利用の注意

GitHub Pages は誰でも開ける公開環境です。`/exec` のURLを知っていれば外部からも投票できます。
設問や回答に社内限りの情報を載せる場合は、この構成が運用ルール上問題ないか事前にご確認ください。
研修のたびに部屋を作り、終了後に「部屋をまるごと消す」で片付ける運用が無難です。
